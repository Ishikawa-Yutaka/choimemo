# Firebase Dynamic Links 廃止と認証方式の違い

## Firebase Dynamic Links 廃止の概要

Firebase Dynamic Links が廃止され、以下の認証機能が利用できなくなる：

- **モバイルアプリのメールリンク認証**（`signInWithEmailLink`）
- **ウェブアプリの Cordova OAuth サポート**

## 2つの認証方式の違い

### 1. メール確認（`sendEmailVerification`）← ちょいMEMOで使用中

メールアドレスが本人のものか確認するだけの機能。ログイン自体はパスワードで行う。

```
ユーザーの流れ:

1. メール + パスワードでアカウント作成
2. Firebaseが確認メールを送信
3. ユーザーがメール内のリンクをクリック
4. → 「このメールアドレスは本人のものです」と確認完了
5. 以降はパスワードでログインし続ける
```

- **リンクの役割**: メールアドレスの本人確認だけ
- **ログイン方法**: メール + パスワード（常に）
- **Dynamic Links**: 使っていない → **廃止の影響なし**

### 2. メールリンク認証（`signInWithEmailLink`）← 廃止の影響を受ける

パスワードを使わず、メールのリンクだけでログインする機能。

```
ユーザーの流れ:

1. メールアドレスだけ入力（パスワードなし）
2. Firebaseが「ログイン用リンク」をメールで送信
3. ユーザーがメール内のリンクをクリック
4. → それだけでログイン完了（パスワード不要）

※ セッションが有効な間は自動ログイン（リンク不要）
※ セッションが切れたら再度リンクでログイン
```

- **リンクの役割**: リンク自体がログインの鍵（パスワードの代わり）
- **ログイン方法**: メールのリンクをクリックするだけ
- **Dynamic Links**: リンクの仕組みに使われている → **廃止の影響あり**

## 比較表

| | メール確認 | メールリンク認証 |
|---|---|---|
| Firebase関数 | `sendEmailVerification` | `signInWithEmailLink` |
| パスワード | 必要 | 不要 |
| メールの目的 | 本人確認 | ログインそのもの |
| リンクの役割 | 確認するだけ | ログインの鍵 |
| Dynamic Links | 不使用 | 使用 |
| 廃止の影響 | **なし** | **あり** |

## ちょいMEMOへの影響

**対応不要。**

- ちょいMEMOはメール + パスワード認証（`signInWithEmailAndPassword`）を使用
- メール確認（`sendEmailVerification`）は Dynamic Links に依存していない
- Cordova も使用していない（React + Vite のウェブアプリ）
- パスワードリセット（`sendPasswordResetEmail`）も Dynamic Links とは別の仕組み
