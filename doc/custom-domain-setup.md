# カスタムドメイン設定手順（Vercel + Xサーバー）

## 全体の流れ

```
Xサーバーでドメイン取得（choimemo.com）
  ↓
Vercelでドメイン追加
  ↓
Xサーバーでdns設定（AレコードをVercelに向ける）
  ↓
DNS反映を待つ（数分〜数時間）
  ↓
Vercelで Valid Configuration（緑色）になれば完了
  ↓
Firebase Console の設定を更新
  ↓
コード内のURL参照を更新
```

## ステップ1: Vercelでドメイン追加

1. Vercel Dashboard → プロジェクトを開く
2. **Settings** → **Domains**
3. `choimemo.com` を入力して **Add**
4. Vercelが**必要なDNSレコード**を表示する

```
表示例:
  Type: A
  Name: @
  Value: 216.198.79.1
```

**注意**: IPアドレスはVercelが指定する最新の値を使うこと。
以前は `76.76.21.21` だったが、`216.198.79.1` に変更された。

## ステップ2: XサーバーでDNSレコード追加

1. Xサーバーのドメイン管理パネルにログイン
2. 対象ドメインの **DNSレコード設定** を開く
3. **既存のNSレコードは絶対に削除しない**（削除するとドメインが機能しなくなる）
4. 以下のレコードを**新規追加**する

| ホスト名 | 種別 | 内容 | TTL | 優先度 |
|---------|------|------|-----|-------|
| (空欄) | A | 216.198.79.1 | 3600 | 0 |

### 用語説明

| 用語 | 意味 |
|------|------|
| **NSレコード** | ドメインのDNSサーバーを指定。**触らない** |
| **Aレコード** | ドメインをIPアドレスに紐づける |
| **CNAMEレコード** | ドメインを別のドメイン名に紐づける |
| **@（ホスト名）** | ドメインそのもの（Xサーバーでは空欄と同じ） |
| **TTL** | キャッシュ保持時間（秒）。3600（1時間）でOK |
| **優先度** | MXレコード（メール用）でのみ使用。A/CNAMEでは0でOK |

## ステップ3: DNS反映を待つ

- 通常は**数分〜数十分**で反映
- 最大で**48時間**かかることもある
- VercelのDomainsページをリロードして **Valid Configuration（緑色）** になれば完了
- SSL証明書（HTTPS）もVercelが自動で設定してくれる

## ステップ4: Firebase Console の設定更新

ドメイン変更後、Firebase側も更新が必要。

### 承認済みドメインの追加

1. Firebase Console → **Authentication** → **Settings**
2. **承認済みドメイン** に `choimemo.com` を追加

※ これを追加しないと、新ドメインからのログインやメール認証が動作しない

### メールテンプレートの操作URL変更

1. Firebase Console → **Authentication** → **Templates**
2. いずれかのテンプレートを開く（例：メールアドレスの確認）
3. 鉛筆アイコン（編集）をクリック
4. **「操作 URL をカスタマイズ」** の値を変更

```
変更前: https://choimemo.vercel.app/__/auth/action
変更後: https://choimemo.com/__/auth/action
```

※ この設定は全テンプレート共通。1箇所変えれば全てに反映される

## ステップ5: コード内のURL参照を更新

ソースコード内に旧ドメインがハードコードされている箇所を検索して更新する。

```bash
# 旧ドメインの参照を検索
grep -r "choimemo.vercel.app" src/ doc/ README.md
```

今回変更したファイル:
- `src/pages/AuthActionPage.tsx` — コメント内のURL
- `README.md` — プロジェクトURL
- `doc/firebase-email-verification-flow.md` — ドキュメント内のURL

## 注意事項

- `choimemo.vercel.app` は削除しなくてOK（そのまま残してもカスタムドメインが優先される）
- 旧ドメイン（vercel.app）でアクセスすると **307リダイレクト** で自動的に `choimemo.com` に転送される
- つまり旧URLのリンクやブックマークが残っていても、ユーザーは新ドメインに誘導される
- Firebase の承認済みドメインには旧ドメインも残しておくと安全

# サブドメイン設定手順（Vercel + Xサーバー）

## 前提知識

### Aレコード変更 vs ネームサーバー変更

| 方法 | 内容 | DNS管理 |
|------|------|---------|
| **Aレコード変更**（今の方法） | Xサーバー上で特定のレコードだけ追加 | Xサーバーのまま |
| **ネームサーバー変更** | DNS管理をVercelに丸ごと移管 | Vercelに移る |

#### Aレコード方式（今の構成）

- Xサーバーでドメインの管理を維持したまま、一部だけVercelに向ける
- メール（MXレコード）など他の設定もXサーバーで引き続き管理できる
- サブドメインを追加するたびにXサーバーでレコードを手動追加する

#### ネームサーバー方式

- DNS管理の全権をVercelに移す
- Vercel Dashboard上でサブドメインを一元管理できてシンプル
- ただしメール等Vercel以外のサービスの設定もVercel側で行う必要がある

#### どちらを選ぶべきか

| 状況 | 推奨 |
|------|------|
| Vercelだけで使う（サブドメイン少数） | Aレコード方式で十分 |
| サブドメインを大量に使う + 全部Vercel | ネームサーバー変更の方が楽 |
| Xサーバーでメールも使いたい | Aレコード方式の方が安全 |

### ルートドメイン vs サブドメインのDNSレコード

| 対象 | レコード種別 | ホスト名 | 内容 |
|------|------------|---------|------|
| ルートドメイン（choimemo.com） | A | (空欄) | 216.198.79.1 |
| サブドメイン（blog.choimemo.com） | CNAME | blog | cname.vercel-dns.com |

- ルートドメインは**Aレコード**（IPアドレスを直接指定）
- サブドメインは**CNAMEレコード**が推奨（別のドメイン名に紐づけ）

## Vercelのプロジェクトとドメインの関係

```
1つのVercelプロジェクト = 1つのGitHubリポジトリ = 1つのアプリ
ドメイン/サブドメインは「プロジェクト」に紐づける
```

### 同じアプリにサブドメインを追加する場合

www.choimemo.com も choimemo.com も同じアプリにしたい場合：

```
choimemo プロジェクト（今のリポジトリ）
  ├── choimemo.com        ← 今ある
  └── www.choimemo.com    ← 同じプロジェクトにドメイン追加
```

→ 同じプロジェクトのSettings → Domainsに追加するだけ。

### 別のアプリをサブドメインで公開する場合

blog.choimemo.com で別のサイトを動かしたい場合：

```
choimemo プロジェクト（リポジトリA）
  └── choimemo.com

choimemo-blog プロジェクト（リポジトリB）  ← 新規作成
  └── blog.choimemo.com
```

→ 別のGitHubリポジトリ + 別のVercelプロジェクトが必要。

## サブドメイン設定の手順（別アプリの場合）

### ステップ1: GitHubに新しいリポジトリを作成

```
GitHub → New repository → 例: choimemo-blog
```

### ステップ2: Vercelで新しいプロジェクトを作成

1. Vercel Dashboard → **Add New Project**
2. 作成したGitHubリポジトリを選択してインポート
3. デプロイが完了すると `choimemo-blog.vercel.app` のようなURLが付与される

### ステップ3: Vercelでサブドメインを追加

1. 新しいプロジェクトの **Settings** → **Domains**
2. `blog.choimemo.com` を入力して **Add**
3. Vercelが必要なDNSレコードを表示する

```
表示例:
  Type: CNAME
  Name: blog
  Value: cname.vercel-dns.com
```

### ステップ4: XサーバーでDNSレコード追加

1. Xサーバーの **DNSレコード設定** を開く（「サブドメイン設定」ではない！）
2. 以下のレコードを**新規追加**する

| ホスト名 | 種別 | 内容 | TTL | 優先度 |
|---------|------|------|-----|-------|
| blog | CNAME | cname.vercel-dns.com | 3600 | 0 |

**注意**: Xサーバーの「サブドメイン設定」機能は使わない。
「サブドメイン設定」はXサーバー自体でホスティングするための機能であり、
Vercelに向ける場合は**DNSレコード設定でCNAMEを追加するだけ**でよい。

### ステップ5: DNS反映を待つ

- VercelのDomainsページをリロードして **Valid Configuration（緑色）** になれば完了
- SSL証明書もVercelが自動設定する

### ステップ6: 自動デプロイの確認

各リポジトリにプッシュすると、それぞれ独立して自動ビルド・デプロイされる：

```
リポジトリA（choimemo）にプッシュ → choimemo.com が更新
リポジトリB（choimemo-blog）にプッシュ → blog.choimemo.com が更新
```

## 注意事項

- Xサーバーの「サブドメイン設定」とDNSの「CNAMEレコード追加」は別物
  - サブドメイン設定 → Xサーバーでホスティングする用（今回は不要）
  - DNSレコード追加 → ドメインの向き先を指定する用（こちらを使う）
- サブドメインごとにVercelプロジェクトが分かれるので、ビルド設定や環境変数も独立して管理できる
- 同じアプリの別名（www付きなど）なら、新しいリポジトリは不要で同じプロジェクトにドメイン追加するだけ
