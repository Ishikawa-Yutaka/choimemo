# モバイルWebアプリの固定レイアウトパターン

## この文書について

モバイルWebアプリで「固定ヘッダー + コンテンツ部分だけスクロール」を実現する手法をまとめたものです。
ちょいMEMOアプリで実際に発生した不具合の解決を通じて学んだ内容です。

---

## 発生した問題

### 問題1: テキストがヘッダーの裏に隠れる

**状況**: スマホで長文メモの一部を削除すると、テキストがヘッダーの下に入り込んで見えなくなる

**原因**: ヘッダーに `position: fixed` を使っていたため

```css
/* 問題のあったコード */
.header {
  position: fixed;  /* ヘッダーがフロー（配置計算）から外れて浮いている */
  top: 0;
  left: 0;
  right: 0;
}

.memo-container {
  padding-top: 52px;  /* 見た目上の隙間を作っているだけ */
}
```

`position: fixed` にすると、ヘッダーは**ページのレイアウトから完全に外れて浮いた状態**になる。
`.memo-container` は画面の一番上から始まっており、`padding-top` で見た目だけ下げているだけ。
ブラウザがスクロール位置を調整すると、padding の中にテキストが入り込み、ヘッダーの裏に隠れてしまう。

```
┌─────────────────────────────────────┐
│  header (浮いている)                  │
├─────────────────────────────────────┤
│  .memo-container                     │ ← 実際は画面の一番上から始まっている
│  ┌─ padding-top: 52px（空白）──┐     │ ← ここにテキストが入り込む可能性がある
│  │                              │     │
│  ├─ textarea ───────────────┤     │
│  │  テキスト...                  │     │
│  └──────────────────────────┘     │
└─────────────────────────────────────┘
```

### 問題2: ヘッダーが画面外にスクロールしてしまう

**状況**: 問題1を修正してヘッダーを通常フローに変更した後も、iOS Safariでテキスト削除時にヘッダーが画面の上に消えてしまう

**原因**: iOS Safariでは `overflow: hidden` だけではビューポート自体のスクロールを防げない

iOS Safariには特有の挙動があり、テキストエリアにフォーカスがある状態でテキスト操作をすると、
`overflow: hidden` を設定していても**ビューポート（画面全体）自体がスクロール**してしまうことがある。

---

## 解決策: `position: fixed` でアプリ全体を固定する

### 最終的なCSS

```css
/* アプリ全体を画面に固定 */
.app {
  position: fixed;
  top: 0;
  left: 0;
  right: 0;
  bottom: 0;

  display: flex;
  flex-direction: column;
  overflow: hidden;
}

/* ヘッダー: 通常のflex子要素として上部に配置 */
.header {
  flex-shrink: 0;  /* 縮まないようにする */
  /* position: fixed は不要 */
}

/* メモコンテナ: ヘッダーの下の残りスペースを占める */
.memo-container {
  flex: 1;
  min-height: 0;     /* flexの子要素がコンテンツ以下に縮めるようにする */
  overflow: hidden;   /* はみ出し防止 */
}

/* テキストエリア: ここだけがスクロールする */
.memo-textarea {
  flex: 1;
  overflow-y: auto;  /* 縦スクロールを有効化 */
}
```

### レイアウト構造

```
画面（ビューポート）
└── .app (position: fixed → 画面に固定、overflow: hidden → スクロールしない)
     ├── header (flex-shrink: 0)     ← .appが動かないので、ここも動かない
     └── .memo-container (flex: 1)   ← ヘッダーの下の残りスペース
          └── .memo-editor
               └── textarea          ← ここだけがスクロールする
```

---

## なぜこれで解決するのか

### ヘッダーが動かない理由

ヘッダー自身に `position: fixed` を付けなくても、**親の `.app` が画面に固定されていて動かないから、中にあるヘッダーも動かない**。

### テキストがヘッダーの裏に入り込まない理由

ヘッダーは通常のflex子要素としてレイアウトに参加している。
`.memo-container` は `flex: 1` で**ヘッダーの下の残りスペースだけ**を占める。
テキストが物理的にヘッダーの位置まで到達できない。

```
修正前:                          修正後:
header (浮いている)              header (フローの一部)
│                                │
memo-container (画面の一番上     memo-container (ヘッダーの
から始まる。paddingで             下から始まる。物理的に
見た目だけ下げている)            ヘッダー領域に入れない)
```

### iOSでビューポートがスクロールしない理由

`.app` に `position: fixed` を設定すると、iOSはこの要素を**ビューポートに完全に固定**する。
通常の `height: 100vh` + `overflow: hidden` だけでは防げないiOS特有のスクロールも、
`position: fixed` なら確実に防げる。

## 各CSSプロパティの役割まとめ

### `.app` のプロパティ

| プロパティ | 役割 |
|---|---|
| `position: fixed` | アプリ全体を画面に固定。iOSのビューポートスクロールを防止 |
| `top/left/right/bottom: 0` | 四辺を画面端に合わせる（= 画面全体を占める） |
| `display: flex` | 子要素をflexboxで配置 |
| `flex-direction: column` | 子要素を縦方向に並べる |
| `overflow: hidden` | この要素自体のスクロールを無効化 |

### `.header` のプロパティ

| プロパティ | 役割 |
|---|---|
| `flex-shrink: 0` | 画面が小さくてもヘッダーが縮まないようにする |

### `.memo-container` のプロパティ

| プロパティ | 役割 |
|---|---|
| `flex: 1` | ヘッダーの下の残りスペース全体を占める |
| `min-height: 0` | flexboxのデフォルトでは子要素はコンテンツサイズより小さくならない。これを0にすることで、テキストが多くてもコンテナがはみ出さない |
| `overflow: hidden` | コンテナからのはみ出しを防止 |

### `.memo-textarea` のプロパティ

| プロパティ | 役割 |
|---|---|
| `flex: 1` | エディター内の残りスペース全体を占める |
| `overflow-y: auto` | テキストが多い時に**ここだけ**縦スクロールする |

---

## `min-height: 0` の補足説明

flexboxには重要なデフォルト動作がある：

```
デフォルト: min-height: auto
→ flex子要素は、中身のコンテンツサイズより小さくならない
→ 長文テキストがあると、コンテナが割り当てられたサイズを超えてはみ出す

min-height: 0 を設定すると:
→ flex子要素は、中身に関係なく自由にサイズを縮められる
→ コンテナは flex: 1 で割り当てられたサイズに収まる
→ はみ出した分は overflow: hidden で非表示（textareaがスクロール担当）
```

## この手法が使われる場面

- モバイルWebアプリ全般
- ネイティブアプリ風のUI（固定ヘッダー/フッター）
- チャットアプリ（ヘッダー固定 + メッセージ部分スクロール）
- メモアプリ（ヘッダー固定 + テキストエリアスクロール）

iOS Safariのビューポートスクロール問題は多くの開発者が遭遇する有名な問題であり、
`position: fixed` でアプリ全体を固定する手法は**定番の解決策**として広く使われている。

---

## 参考: 問題が起きやすい環境

- **iOS Safari**: 最も問題が起きやすい。`overflow: hidden` だけでは不十分
- **Android Chrome**: 比較的問題が少ないが、同じ手法を使っておくと安全
- **PC ブラウザ**: 基本的に問題は起きないが、統一した実装にしておくのが良い
