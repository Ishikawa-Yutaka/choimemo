# セッション履歴スタックと replace ナビゲーション

## この文書について

ブラウザの「戻る」ジェスチャーで古いページに戻ってしまう不具合の原因と対策をまとめる。
ちょいMEMOのメール確認フローで発生した実際の不具合を例に使用。

---

## 1. 2種類の「履歴」の違い

| | ブラウザ履歴 | セッション履歴スタック |
|---|---|---|
| 正体 | 過去に訪問したサイトの一覧 | **今のタブ内**で遷移したページの積み重ね |
| 保存先 | ディスクに永続保存 | メモリ上（一時的） |
| いつ消える | 手動で削除した時 | タブを閉じた時 |
| ブラウザの「履歴削除」で消える？ | はい | **いいえ** |
| 「戻る」ボタンが使うのは？ | いいえ | **はい** |

### セッション履歴スタックとは

タブを開いてからの画面遷移を積み上げたもの。JavaScript では `window.history` でアクセスする。

```
1ページ目を開く   → スタック: [A]
2ページ目に遷移   → スタック: [A] → [B]
3ページ目に遷移   → スタック: [A] → [B] → [C]
                                            ↑ 今ここ

「戻る」を押す    → スタック: [A] → [B] → [C]
                                    ↑ ここに戻る
```

ブラウザのキャッシュや履歴を削除しても、**今のタブ内の操作で新しく積み上がる**ため無関係。

## 2. 発生した不具合

### 症状

メモページで左→右にスワイプすると「エラーが発生しました」画面が表示される。

### 原因

メール確認後の画面遷移に `replace` を使っていなかったため、
確認用URLがセッション履歴に残っていた。

```
メール確認リンクをクリック:
  スタック: [/__/auth/action?oobCode=xxx]

「ちょいMEMOを始める」をクリック（replace なし）:
  スタック: [/__/auth/action?oobCode=xxx] → [/]
                                             ↑ 今ここ

メモページで戻るジェスチャー:
  スタック: [/__/auth/action?oobCode=xxx] → [/]
            ↑ ここに戻る
  → 期限切れのoobCodeで再処理 → エラー
```

## 3. navigate の通常遷移と replace の違い

### 通常の遷移（デフォルト）

```typescript
navigate('/')
// または
<Link to="/">ちょいMEMOを始める</Link>
```

```
遷移前: [A] → [B]
                ↑ 今ここ

遷移後: [A] → [B] → [/]
                      ↑ 今ここ
（B が履歴に残る → 「戻る」で B に戻れる）
```

### replace: true

```typescript
navigate('/', { replace: true })
// または
<Link to="/" replace>ちょいMEMOを始める</Link>
```

```
遷移前: [A] → [B]
                ↑ 今ここ

遷移後: [A] → [/]    ← B が / に置き換わった
                ↑ 今ここ
（B は消えた → 「戻る」で B には戻れない）
```

---

## 4. replace: true を使うべき場面

| 場面 | 理由 |
|---|---|
| ログイン成功後の遷移 | ログイン画面に戻る必要がない |
| メール確認成功後の遷移 | 確認URLに戻ると期限切れでエラー |
| ログアウト後の遷移 | メモページに戻るとエラー |
| リダイレクト全般 | 中間ページに戻る意味がない |

### 判断基準

**「戻る」で元のページに戻ったとき、ユーザーにとって意味があるか？**

- 意味がある（一覧→詳細など） → 通常の遷移
- 意味がない（ログイン→メインなど） → `replace: true`

## 5. 今回の修正内容

### AuthActionPage.tsx の変更

```typescript
// 修正前: 成功画面を表示して、Linkで遷移（replaceなし）
setStatus('success')

// 修正後: 自動でメモページに遷移（replace: true）
navigate('/', { replace: true })
```

### 追加の安全策

```typescript
// 既にメール確認済みのユーザーが戻るジェスチャーで再アクセスした場合
// エラーを表示せずメモページにリダイレクト
if (user?.emailVerified) {
  navigate('/', { replace: true })
  return
}
```

## 6. 横スワイプによるブラウザ「戻る」の防止策（補足）

セッション履歴の問題に加え、iOS Safariの画面端スワイプが「戻る」として発動する問題もある。
以下の対策をアプリ全体に適用している。

### CSS: touch-action: pan-y

```css
.app {
  /* 横方向のタッチ操作はJSで処理、ブラウザに任せない */
  touch-action: pan-y;
}
```

### JS: touchmove の preventDefault

```typescript
// 横スワイプを検知したら、ブラウザのデフォルト動作を即座にブロック
document.addEventListener('touchmove', (e) => {
  const diffX = Math.abs(e.touches[0].clientX - startX)
  const diffY = Math.abs(e.touches[0].clientY - startY)
  if (diffX > diffY) {
    e.preventDefault()
  }
}, { passive: false })
```

### 根本対策との関係

| 対策 | 効果 |
|---|---|
| `replace: true` で遷移 | 戻る先をなくす（**根本対策**） |
| `touch-action: pan-y` | ブラウザの横スワイプ解釈を抑制 |
| `touchmove` の `preventDefault` | ブラウザの戻るジェスチャーをブロック |

**最も重要なのは `replace: true`**。スワイプ防止はあくまで補助的な対策。
